**Schema source:** `migrations/0001_applications.sql`.

## Table fields

| Column | Meaning |
|---|---|
| `id` | Random UUID generated for the insert attempt; primary key |
| `cycle` | Recruitment cycle from `DEFAULT_CONFIG.cycle` |
| `name`, `email` | Required identity/contact text; email uses SQLite `NOCASE` collation |
| `reg_no` | Optional organization/registration text; stored as SQL `NULL` when blank |
| `background` | Year or background key such as `grad` or `other` |
| `roles` | JSON text array; `CHECK (json_valid(roles))` requires valid JSON |
| `other_role` | Optional detail for the specialized role |
| `motivation` | Required answer to the “why” prompt |
| `experience` | Optional experience text |
| `links` | JSON text array with a valid-JSON check |
| `hours_per_week` | Numeric availability constrained to 3 through 40 |
| `consent` | Integer constrained to exactly `1` |
| `created_at`, `updated_at` | UTC timestamp text generated by SQLite when inserted |

The uniqueness constraint is `UNIQUE (cycle, email)`. Since email is
case-insensitive, the same address with different capitalization in the same
cycle identifies one application. A new cycle can have a separate row.

## Insert-or-update behavior

The prepared SQL inserts a random ID and normalized values. If the unique
cycle/email pair already exists, `ON CONFLICT(cycle, email) DO UPDATE` replaces
the editable answers and updates `updated_at`. It does not replace the row ID,
cycle, or email. `created_at` remains the original creation time.

This makes repeat submissions idempotent for a person and cycle: the applicant
can revise one application instead of creating multiple copies. The server
currently returns `status: "received"` for both the first insert and later
updates, so the client cannot distinguish them from that response today.

## SQL safety

The SQL statement uses `?` placeholders. `.bind(...)` supplies each value in
order; D1 treats them as data, not SQL syntax. Do not change it to concatenate
untrusted strings into SQL.

`JSON.stringify(data.roles)` and `JSON.stringify(data.links)` convert arrays
into JSON strings because the schema stores those columns as text. The
`json_valid` checks make SQLite reject invalid JSON text if a future writer
skips the Function's validation.
